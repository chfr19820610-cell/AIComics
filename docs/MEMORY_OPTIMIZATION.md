# 内存优化指南（加速 840 镜生成）

> 写于 2026-11-16 02:27（Round 42）
> 问题：h3stream 每步从 71 秒变 120 秒，全季从 161 小时变 252 小时

---

## 一、现状

| 指标 | 值 |
|---|---|
| h3stream 自身 RSS | 448 MB |
| 系统 free | 54-55% |
| **swap 已用** | **2.7 GB / 4 GB**（余 1.4 GB） |
| 每步耗时 | **约 2 分钟**（之前 1-1.5 分钟） |
| 单镜耗时 | **约 18 分钟**（之前 14 分钟） |
| 全季预估 | **约 252 小时（10.5 天）** |

---

## 二、为什么 swap 会拖慢

h3stream 的工作方式：
```
每步：从磁盘读 50 层 DiT 权重 → 内存 → GPU 计算
```

**如果内存不够**：
```
磁盘 → swap（磁盘）→ 内存 → GPU
        ↑ 多了一次磁盘往返
```

**结果**：每步慢 70%

---

## 三、谁在占内存

| 应用 | 内存 | 说明 |
|---|---|---|
| **Chrome（3 进程）** | **1377 MB** | 最大占用，其中 DSH GUI 占一个 |
| **OrbStack** | **805 MB** | Docker 容器（thriftllm 已停，可能没在用） |
| node | 496 MB | 可能是 DSH GUI 服务，不能关 |
| h3stream | 448 MB | 需要保留 |
| hermes-agent | 373 MB | 可能是服务 |
| AlComics local | 102 MB | 可能是本地 ComfyUI 等 |

**总计约 3.6 GB**

---

## 四、三个选项

### 选项 A：保持现状（不关任何应用）

| 项 | 值 |
|---|---|
| 单镜 | 18 分钟 |
| 全季 | **252 小时（10.5 天）** |
| 风险 | 无 |
| 适合 | 峰哥需要正常用电脑 |

---

### 选项 B：关 OrbStack（推荐，如果没用 Docker）

| 操作 | 效果 |
|---|---|
| `osascript -e 'quit app "OrbStack"'` | 释放 805 MB |
| 预期 swap | 2.7GB → 1.9GB |
| 预期单镜 | 18 → 15 分钟 |
| 全季 | 252 → 210 小时（**省 42 小时**） |

**注意**：如果 Docker 有重要容器在跑，不要关。

**当前 Docker 状态**（上次检查）：
- thriftllm 已停（4 容器 down）
- 其他容器：需要确认

---

### 选项 C：关 Chrome 多余标签 + OrbStack

| 操作 | 效果 |
|---|---|
| 关 Chrome 非 DSH 标签（保留 1 个） | 释放 约 900 MB |
| 关 OrbStack | 释放 805 MB |
| 预期 swap | 2.7GB → 1.0GB |
| 预期单镜 | 18 → **12 分钟** |
| 全季 | 252 → **168 小时**（**省 84 小时**） |

**风险**：如果峰哥在用 Chrome 查资料/看视频，会不方便。

---

## 五、我的建议

**推荐选项 B**（关 OrbStack）：
- 如果不用 Docker，这是"零成本"的优化
- 省 42 小时
- 不影响峰哥日常使用

**如果想更快**：选项 C（也关 Chrome 标签）→ 省 84 小时。

**如果不确定**：保持选项 A（252 小时），反正能跑完。

---

## 六、怎么验证优化生效

```bash
# 1. 关掉应用后，看 swap
sysctl vm.swapusage

# 2. 看 h3stream 的 step 时间（run-dir 里 latents-step 的时间间隔）
ls -lt /Users/eric/Desktop/hermes/tools/minimax-h3-stream-mac/runs/p6_E01_S*/latents-step-*.npz | head -5

# 3. 如果每步回到 1-1.5 分钟，说明优化生效
```
