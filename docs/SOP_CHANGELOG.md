## 2026-11-16 · §17 风格漂移精确规律

**触发**：P6 跑 E01 前 8 镜时抽帧发现风格割裂

**新增内容**：
- 三层规律表（第三次验证）：
  - `closeup`/`extreme_closeup` → 赛璐璐动漫 + 粗描边
  - `wide`/`environment`/群像 → 3D 写实 CG
  - `medium` → 混合（偏动漫）
- 根因分析：H3 训练数据分布（人物特写多为动画截图，宏大场景多为电影 CG）
- 三种应对方案对比（接受混搭 / 限制景别 / 强 prompt 工程）
- **4 条硬规则**：
  1. 分镜阶段标注 `style_risk`
  2. 每集 ≥70% 镜头是 closeup/medium
  3. wide 镜只用于建立镜头（≤8 个/集）
  4. 验收抽检 3 wide + 3 closeup
- E01 实测分布：动漫 40% / 中 37% / CG 23%（达标）

## 2026-11-16 · §16 音画对齐规范

**触发**：峰哥指出"口型、声音、字幕全对不上"

**新增内容**：
- 根因：我们是"先画面后配音"（顺序错了）
  - 引行业文章原话："正确工作流的第一步，一定是先把配音定死"
- 正确工作流（7 步）：
  1. 写台词
  2. Piper TTS 测每句精确时长
  3. 有台词镜 = TTS 时长 + 0.4s；无台词镜 = 3.0s
  4. 帧数取 17*n+5 网格
  5. h3stream `--frames` 精确生成
  6. 字幕用 TTS 实测 → 零误差
  7. 拼接不再 -shortest 硬裁
- 口型处理：镜头语言「藏」
  - **有台词镜禁止 closeup**，自动降级 medium
- 技术约束记录（4 条）
- **5 条硬规则**

**实测**：E01 总时长 203.71s = 3.40 分钟，字幕误差 0.02s

## 2026-11-16 · §17.6 四层规律修正

**触发**：E01 抽帧逐镜检查（S09/S10 对比）

**修正内容**：
- 原「三层规律」不够精确，修正为**四层**：
  1. 单人 closeup → 正常赛璐璐动漫（唯一稳定来源）
  2. 双人/多人 medium → 赛璐璐 + 偏 Q 版
  3. wide/environment（无人）→ 3D 写实 CG
  4. action → 混合

**关键洞察**：
- 画面出现 2+ 正脸 → 向 Q 版漂移
- 画面无人物 → 向写实 CG 漂移
- **只有「单人特写」是稳定的动漫来源**

**新增硬规则**：
- 双人对话镜改用 `over_shoulder`（过肩，只有一人正脸）
- 群像镜 ≤5 个/集
- 目标：closeup + over_shoulder 占比 ≥60%

**实测**：E01 10 镜样本约 50% 达标

## 2026-11-16 · §17.7 描述具体性决定风格

**触发**：S11 是 closeup 却出 3D 写实（与 S09 割裂）

**发现**：
- S09 closeup + 情绪化描述（水珠坠落/嘴唇紧抿）→ 赛璐璐动漫 ✅
- S11 closeup + 材质化描述（锦袍金线反光/晨光）→ 3D 写实 CG ❌

**完整规律**：风格 = 景别 × 描述类型

**硬规则**：
- closeup 描述禁止：反光/光泽/金属/绸缎/景深/虚化
- closeup 描述必须含：情绪词 + 动作词
- 写实向描述留给 wide/environment

**代价**：E01 内风格混搭（无法在不重跑的前提下修复）

## 2026-11-16 · §18 验收标准的版本一致性

**触发**：7 gate 里有 5 个还在检查旧 6 镜结构（会假通过/永远失败）

**核心教训**：
> 比代码 bug 更危险的是验收标准过期。
> 代码 bug 会让你做错，过期的验收标准会让你以为自己对了。

**具体问题**：
- g1/g3 检查 `scripts/$ep.json`（旧数据）→ 假通过
- g4 `!= 6` → 永远失败
- g5 路径过时 → 永远失败
- g6 无时长检查 → 3-4 分钟目标无人验证

**硬规则**：
1. 数据结构变更必须同步更新所有 gate 的数据源
2. gate 必须检查"当前版本"的数据
3. gate 检查项要随目标变化（18 秒 → 3-4 分钟）
4. 改造后立即跑 gate，看结果是否符合预期

**修好 gate 后抓出的三层数据问题**：
1. 7 集只有 1 幕（act_id 全填 underdog）
2. E10 只有 7 句台词
3. E12 的 S25.action 为空

**最终 7 gate**：5 PASS + 1 CONDITIONAL + 2 预期 FAIL

## 2026-11-16 · §19 数据格式一致性

**触发**：5 集 shot_type 是中文（大特写/近景），导致口型保护静默失效

**核心教训**：
> 最隐蔽的 bug 不是报错的 bug，是「静默失效」的 bug。
> 它不报错，不崩溃，只是悄悄不做该做的事。

**具体问题**：
```python
DOWNGRADE = {"closeup": "medium", "extreme_closeup": "medium"}
# 中文 "大特写" 不匹配 → 不降级 → 口型暴露（无报错）
```

**实测影响**：E02/E03/E05/E06/E12 共 49 镜本该降级但不会降级

**为什么危险**：E01 恰好是英文（会正常降级），峰哥看第一集会以为没问题

**硬规则**：
1. 所有枚举型字段必须是固定值集合
2. 扩写后立即做字段格式校验
3. 关键逻辑（如降级）要有日志，不能静默
4. 测试必须覆盖"中文输入"的失效场景

**修复**：中文 → 英文映射，12 集全统一，89 镜降级生效

## 2026-11-16 · §17.8 动作词压过材质词

## 2026-11-16 · §20 数据流一致性（最严重教训）

**触发**：S16 是特写，但 alignment 声称已降级到 medium

**根因**：
```
align_episode → alignment.json（medium）✅
              ✗ 没改 prompts（仍是 Extreme close-up）
h3stream 用 prompt，不用 alignment
→ 实际生成 extreme_closeup（口型暴露）
```

**影响**：89 镜本该降级但没降。SOP §16 的口型保护形同虚设。

**为什么 61 轮才发现**：一直在看 alignment.json，从没检查 prompt 的实际景别前缀。

**核心教训**：
> 验证「中间表示」没用，要验证「最终输入」。
> 改了一层，必须验证下一层有没有跟着改。

**硬规则**：
1. 降级/变换逻辑必须同时改中间表示和最终输入
2. 验证要在最终输入层做（模型只看 prompt）
3. 加自动校验（validate_prompts.py）
4. 多级数据流要有端到端检查

**修复**：89 条降级 + 391 条前缀对齐。验证 0 不匹配。

**与 §18/§19 的关系**：
- §18 验收工具错了（假通过）
- §19 输入格式错了（静默失效）
- §20 变换没传播到最终输入（下游收不到变更）
共同点：系统看起来正常，但没做该做的事。

## 2026-11-16 · §21 验证方法学

**触发**：分类器把 E01 的 3 镜误判为 CHIBI，抽帧发现全错

**根因**：
1. FACE_WORDS 有歧义"面"字
2. CHIBI 优先级过高
3. EMOTION_WORDS 缺关键动作词（92 个里没有"捏住"）

**修正**：EMOTION_WORDS 92→220，FACE_WORDS 精确化，优先级重排

**效果**：
- E01 动漫率 21-25% → **46%**
- E01 Q版 3 镜 → **0**
- 全季动漫率 49% → **57%**
- 全季 Q版 41 镜 → **0**

**核心教训**：
> 工具看起来正常，但结果是错的。
> 解法：用真实样本抽帧验证工具。
